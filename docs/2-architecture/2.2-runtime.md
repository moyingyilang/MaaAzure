# 2.2 · 运行时模型

**位置**：`2-architecture` › 2.2 ｜ 前置：[2.1](2.1-layers.md) ｜ 后继：[2.4 FFI](2.4-ffi.md)

## 进程树

```
maazure-daemon（1 个进程）
├── tokio runtime
│   ├── HTTP/WS 服务
│   ├── 调度器（tick 1s，单线程）
│   └── supervisor（每实例 1 个 task）
└── 子进程：实例 worker（默认 process-per-instance）
    ├── Controller（ADB → 模拟器）
    ├── Resource（bundle）
    ├── Tasker（Pipeline 执行器，C++ 线程池）
    └── Custom 回调（Rust，跑在 C++ 工作线程上）
```

**为什么 process-per-instance**：MaaFramework 在 ADB 断开 / 驱动卡死时可能让 Tasker 卡住；
进程隔离保证一个实例挂了不影响其他实例与 Web。与旧版 `multiprocessing.Process` per config 语义一致。
单实例调试用 `--in-process` 关掉隔离。

## 一帧的时序（委托为例）

```
t=0  node "commission_enter"  → TemplateMatch 命中
t=1  action Click(target)     → 投递点击（异步）
t=2  pre_delay 200ms + post_wait_freezes 500ms
t=3  next: ["commission_page", "commission_empty", "[JumpBack]global_recover"]
t=4  "commission_page" 命中 → action Screencap（只为驱动下一节点）
t=5  next: ["commission_pick", ...] → Custom 回调进入 Rust
       ├─ OCR 结果已在 Detail 里（不用自己截图）
       ├─ 解析 4 个 Duration → 选最短 → 算坐标
       └─ post_click(x, y)（不 wait）
t=6  返回 true → next: ["commission_confirm", ...]
t=7  … 直到某节点 next 为空（任务结束）或命中 [JumpBack]（回锚点）
```

## 线程规则（违反必崩）

| 规则 | 原因 |
|---|---|
| Custom 回调内**禁止**阻塞（IO / sleep / block_on） | 回调跑在 C++ 工作线程，阻塞=整条流水线停摆 |
| 禁止持锁跨 FFI | 锁内只操作内存 |
| 点击一律异步投递 | 需要确认就用 `post_wait_freezes` |
| 长逻辑每步检查 `stopping()` | 否则用户点停止没反应，只能杀进程 |
| 共享状态不放 `Controller` | Controller 非 `Send`/生命周期受限 |

## 看门狗（放在 runner，不放在 Pipeline）

旧版把「60 秒无操作 → `GameStuckError`」「15 次操作同一按钮 ≥12 次 → `GameTooManyClickError`」
写在 `ModuleBase` 里，每个模块都能享受。新线用 `EventSink` 统一实现：

```
EventSink
├── on_node_recognition  → 记录 (frame, node, hit)
├── on_node_action       → 记录 (node, action, target)；累加按钮点击次数
└── on_node_next_list    → 记录候选与最终选择
```

两条阈值检查在 `on_node_action` 里做，命中即 `Tasker::post_stop()`。
好处：**所有任务自动获得保护**，不需要每个任务自己判。

## 日志与可观测

| 输出 | 内容 | 保存在哪 |
|---|---|---|
| 结构化日志 | `tracing`，字段 `instance`/`task`/`frame`/`node` | `log/<instance>/<date>.log`（轮转） |
| 决策轨迹 | `(frame_seq, node, hit, action, target)` NDJSON | `log/<instance>/decisions.ndjson` |
| 截图归档 | ring buffer 最近 200 帧（JPEG q75 ≈ 6MB） | 出错时打包为 `crash-<ts>.zip` |
| 实时画面 | WS 推 JPEG | 不落盘 |

比旧版多两样：**决策轨迹**（可直接转 golden corpus）与 **200 帧**（旧版只存 1 张，复盘不够）。

## 帧预算

| 阶段 | 预算 | 手段 |
|---|---|---|
| 截图 | 由 MaaFW 决定 | 720 短边归一化 + 模拟器原生截屏 |
| 模板匹配 | < 3 ms | ROI 必填，禁止全屏扫 |
| OCR | 30–80 ms | ROI 收紧；能模板就别 OCR |
| Rust 决策 | **< 2 ms** | 纯内存计算 |
| 地图检测 | < 15 ms | 唯一允许超 100ms 的例外，超标先缩 ROI 降采样 |

**不要为毫秒级收益引入异步复杂度。** 单帧 350ms 里 99% 是等截图。
