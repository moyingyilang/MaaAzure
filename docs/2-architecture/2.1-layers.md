# 2.1 · 分层与依赖

**位置**：`2-architecture` › 2.1 ｜ 前置：[1.1 决策](../1-foundation/1.1-decisions.md) ｜ 后继：[2.2 运行时](2.2-runtime.md)

## 四层树

```
crates/
├── foundation/                    1 地基 —— 不含碧蓝航线知识
│   ├── core/        maazure-core      错误树 / 几何 / 任务结果
│   └── vision/      maazure-vision    数字纠错 / 时长 / 几何变换
│
├── domain/                        2 领域 —— 只有碧蓝航线知识
│   ├── battle/      maazure-battle    战役 · 地图 · 战斗 · 大世界
│   └── daily/       maazure-daily     日常任务的最小决策
│
├── runtime/                       3 运行时 —— 只有 MaaFramework
│   └── runner/      maazure-runner    Engine trait / Tasker / 调度器
│
└── apps/                          4 应用 —— 只有入口
    ├── daemon/      maazure-daemon   守护进程
    └── xtask/       xtask            转换与校验工具
```

## 依赖方向（严格单向）

```
apps/daemon ──▶ runtime/runner ──▶ domain/battle ──▶ foundation/vision ──▶ foundation/core
    │                 │                   │                    │
    │                 └──▶ domain/daily ──┴────────────────────┘
    └──▶ foundation/core

apps/xtask ──▶ foundation/core        （只读旧仓数据，不碰运行时）
```

规则：

| 规则 | 校验方式 |
|---|---|
| 只能依赖**同层或更低层** | `cargo tree` + CI 检查 |
| `domain/**` 不得 `use maa_framework` | `grep` 门禁 |
| `foundation/**` 不得依赖任何业务 crate | `Cargo.toml` 审阅 |
| `apps/**` 不含逻辑，只做装配 | review |

## 为什么这么切

**旧仓的问题不是代码多，是依赖乱。** `module/base/`（4,198 行）被所有模块引用，
里面既有纯几何工具，也有 OCR 后处理、有重试装饰器、有配置读取——改一处，全部受影响。

新切法的硬收益：

| 层 | 能在什么环境测试 | 原因 |
|---|---|---|
| `foundation` | 任何机器（含无 SDK 的 Termux） | 零依赖 |
| `domain` | 任何机器 + 录像回放 | 不碰设备 |
| `runtime` | 需要 MaaFramework SDK | 唯一 FFI |
| `apps` | 端到端 | 装配 |

**这就是 DEC-012 的兑现方式**：`cargo test` 在本机跑通 16 个测试，
不需要模拟器、不需要 SDK、不需要网络。

## crate 规模目标

| crate | 目标行数 | 内容 |
|---|---|---|
| `foundation/core` | < 800 | 类型与错误，多了说明抽象失控 |
| `foundation/vision` | < 800 | 后处理，多了说明该进 `domain` |
| `domain/battle` | 8k–15k | 地图 + 战役 + 战斗（P2 后可能再拆子树） |
| `domain/daily` | 2k–4k | 只放「挑一个」类决策 |
| `runtime/runner` | 4k–6k | FFI + 调度 + 事件 |
| `apps/daemon` | 3k–5k | HTTP/WS/MCP |
| `apps/xtask` | 1k–2k | 转换器 |

总计 **20k–35k 行 Rust** + 8k–12k 行 Pipeline JSON + 自动生成的 data JSON。
对比旧仓 288k 行，维护面积约 **1/6**。

## 反模式

| 反模式 | 症状 | 修法 |
|---|---|---|
| 地基依赖领域 | `foundation/core` 里出现 `Commission` | 把类型搬到 `domain` |
| 领域依赖运行时 | `domain/battle` 里 `use maa_framework::Context` | 用 `Engine` trait 的抽象接口 |
| 应用含逻辑 | `apps/daemon` 里出现「如果血量低于 30%」 | 搬到 `domain` |
| 万能 util | 出现 `foundation/core/src/utils.rs` | 按用途拆文件 |
