# 3.2 · 节点树

**位置**：`3-authoring` › 3.2 ｜ 前置：[3.1 规范](3.1-pipeline-spec.md) ｜ 后继：[3.3 示例](3.3-examples.md)

节点不是平铺的清单，是一棵树：**公共底座 → 领域子树 → 任务入口**。
新增任务时，先找到它在树上的位置，再写节点。

## 全树

```
global_*                       0-common：所有任务的祖先
├── global_home                主界面（anchor: home）
├── global_popup_close         通用弹窗关闭
├── global_recover             任意失败后的归位
└── global_login               启动/登录/公告

1-daily                        日常
├── commission_*               委托：enter page empty pick confirm done
├── dorm_*                     宿舍：enter collect fill done
├── research_*                 科研：enter collect project done
├── tactical_*                 战术学院
├── meowfficer_*               指挥喵
├── exercise_*                 演习
├── guild_*                    大舰队
├── gacha_*                    建造
├── reward_*                   奖励领取
├── shop_*                     商店（含 shop_event_*）
├── daily_*                    每日任务
├── hard_* / sos_*             困难图 / SOS
├── mission_* / awaken_*       任务 / 觉醒
└── retire_* / equipment_*     退役 / 装备

2-battle                       战斗
├── campaign_*                 战役外壳：chapter prepare in_map combat map_end result
├── combat_*                   战斗内：start auto manual result
└── map_*                      地图操作（多为 Custom 节点的占位）

3-world                        大世界（P3）
├── os_*                       进图/港口/交换
├── os_ash_*                   余烬/信标
└── os_shop_*                  商店
```

## 每棵子树的固定形状

任何 `<domain>_*` 子树都必须有这五个节点，缺一个就是设计没做完：

```
<domain>_start      入口（DirectHit，指向进页节点）
<domain>_enter      从主界面进入该功能页
<domain>_page       功能页已确认（作为其它节点的公共 next 目标）
<domain>_done       结束（next 为空）
<domain>_recover    异常归位（next: [Anchor]home）
```

之所以强制：`pipeline-check` 可以据此判断「这个任务写完了没有」，
而不是靠人肉 review 每个 JSON。

## 叶子节点的三种形态

| 形态 | 识别 | 动作 | 例 |
|---|---|---|---|
| **看** | TemplateMatch / ColorMatch | `DoNothing` | `<domain>_page` |
| **点** | TemplateMatch | `Click` | `<domain>_enter` |
| **读** | OCR / Custom | `DoNothing` 或 `Custom` | `commission_pick` |

## 归属判据

| 问题 | 归属 |
|---|---|
| 所有任务都会用？ | `0-common` |
| 只在一个功能页里？ | 该 `1-daily/<domain>/` |
| 跨功能页的流程控制？ | 该任务的 `entry.json` |
| 需要计算/记忆？ | 不是节点，去 `domain/` crate |

## 节点计数预算

| 子树 | 预计节点 | 其中 Custom |
|---|---|---|
| `0-common` | 12–15 | 0 |
| 一个日常任务 | 30–60 | 0–2 |
| `2-battle` 战役 | 15–25 | 3–5 |
| `3-world` | 40–60 | 6–10 |

日常任务若出现 **≥3 个 Custom 节点**，说明该任务被误判成「纯流程」——
回头查 [1.2 边界](../1-foundation/1.2-boundaries.md)，很可能它本该进 `domain/daily`。

## 生成物与手写物

```
resource/pipeline/
├── gen/                 ← xtask 自动生成，禁止手改（2,382 个叶子）
└── 0-common/ 1-daily/   ← 手写（拓扑才是领域知识）
```

`gen/` 里的节点 `next` 一律为空；把它们接起来才是写任务。
