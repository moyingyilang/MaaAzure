# A7 · 路线图与验收

## 1. 总览

| 阶段 | 目标 | 量产交付 | 估时（单人全职） |
|---|---|---|---|
| **P0** | 证明链路 + 建立回归网 | 委托任务端到端跑通 | 3–4 周 |
| **P1** | 20 个日常任务 | 日常全套 24h 无人值守 | 5–8 周 |
| **P2** | 战役 / 战斗 / 地图检测 | 主线推图 parity | 6–10 周 |
| **P3** | 大世界 / 岛屿 / 科研重模块 | 全功能 parity | 10–16 周 |
| **P4** | 外围与发布 | 可发布单目录包 | 4–6 周 |

**合计 9–14 个月单人；3 人并行 5–7 个月**（P1 完成后 P2/P3 可拆开并行，
P4 从 P2 起可穿插进行）。

## 2. P0 · 链路验证（3–4 周）

### 交付物

1. `tools/record_golden.py` 在冻结的旧仓里跑通，产出 **12 个用例**（A6 §7）
2. `crates/` 六个 crate 骨架，`cargo check` 通过（本机 Termux 即可，不依赖 SDK）
3. chroot 构建链跑通 `aarch64-unknown-linux-gnu`，能加载 `MAA-linux-aarch64`
4. `resource/` 由 `xtask convert-images` + `convert-assets` 生成，`pipeline-check` 全绿
5. 委托任务：`CommissionStart` → … → `commission_done`，在真实模拟器上跑通
6. `maazure-daemon` 能启动、能列出实例、能看实时截图

### 验收标准（DoD）

- [ ] 委托任务连跑 **20 次无人工干预**
- [ ] 同一段录像回放，决策与旧版一致（L1+L2 断言，A6 §5）
- [ ] `cargo test --workspace` 在 CI 与本机均通过
- [ ] 帧耗时实测记录：截图 / 模板 / OCR / Rust 决策，四项分别列出
- [ ] **DEC-007 结论**：`display_short_side: 720` 缩放后的模板匹配阈值漂移实测值
- [ ] **GIF 模板数量统计**完成，并给出处理策略

> P0 的产出不是「一个能用的委托脚本」，而是「一条被验证过的生产线 + 一张回归网」。
> 委托只是用来证明生产线能出货的样品。

## 3. P1 · 日常任务（5–8 周）

### 范围（20 个任务，按旧版优先级）

| 组 | 任务 |
|---|---|
| 高频短周期 | Commission、Tactical、Research、Dorm、Meowfficer |
| 每日一次 | Exercise、Guild、Gacha、Reward、ShopFrequent、Daily、Hard、Sos |
| 长周期 | Mission、Awaken、Retire、Enhance、Equipment、Shipyard、PrivateQuarters |

### 交付物

- 20 个任务的 Pipeline 拓扑（人工）+ 必要的 Rust Custom（估计 5–8 个）
- 调度器（NextRun / 优先级 / 失败计数）
- `interface.json` 裁剪版（每任务 3–8 个可调项，A3 §4）
- 通知渠道（沿用旧版配置语义）
- 每个任务 1 个 golden 用例

### DoD

- [ ] 24h 连续运行，无人工接管，无卡死
- [ ] 配置热重载生效（改 `config.json` 后下一轮任务用新值）
- [ ] 任一任务连续失败 3 次 → 该任务停摆 + 通知，**其他任务继续**（有意变更，见 A8 §4）
- [ ] 断连一次（拔 ADB）能自动重连并回到主界面
- [ ] 单实例内存 < 300MB，CPU 空闲时 < 3%

### DoD

## 7. 任务迁移矩阵（93 个任务全量）

| 难度 | 特征 | 任务数 | 处理方式 | 阶段 |
|---|---|---|---|---|
| **A** | 纯点击序列 | ~35 | 只写 JSON | P1 |
| **B** | 点击 + OCR 判读 | ~25 | JSON + 1 个 Custom | P1–P2 |
| **C** | 需要寻路 / 阈值决策 | ~20 | JSON 外壳 + Rust 状态机 | P2 |
| **D** | 大型状态机（大世界/岛屿） | ~13 | 独立 crate 子模块 | P3 |

**先做 A 类**：它们能最快验证 Pipeline 规范是否够用，且 A 类写出来的拓扑是 B/C 类的基础。
若 35 个 A 类任务里有 3 个以上被迫写 Custom，说明 A2 的规范需要修订——这是 P1 的重要信号。

## 8. 里程碑风险阀

每个阶段结束时回答三个问题，任一为「否」就**不进入下一阶段**：

1. **回放网覆盖率**：本阶段交付的模块，是否有对应用例？（要求 100%）
2. **旧版可回退**：用户此刻切回旧版，数据/配置是否完好？
3. **单人可维护**：新增一个同难度任务，是否需要 1 天以内？

第 3 条最重要：如果写一个新任务还是要改 5 个文件，说明抽象没做对，
继续堆功能只会把 288k 行的坑原样搬到 Rust。
