# 6.1 · 路线图

**位置**：`6-plan` › 6.1 ｜ 前置：[2.3 模块映射树](../2-architecture/2.3-module-tree.md) ｜ 后继：[6.2 任务树](6.2-task-tree.md)

## 总览

| 阶段 | 目标 | 交付 | 单人全职 |
|---|---|---|---|
| **P0** | 证明链路 + 建回归网 | 委托跑通 | 3–4 周 |
| **P1** | 20 个日常任务 | 日常 24h 无人值守 | 5–8 周 |
| **P2** | 战役 / 战斗 / 地图检测 | 主线推图 parity | 6–10 周 |
| **P3** | 大世界 / 岛屿 / 科研重模块 | 全功能 parity | 10–16 周 |
| **P4** | 外围与发布 | 可发布单目录包 | 4–6 周 |

合计 **9–14 个月单人**；3 人并行 **5–7 个月**（P1 后 P2/P3 可拆开，P4 从 P2 起穿插）。

## P0 · 链路验证（3–4 周）

```
① 录 12 个用例 ──▶ ② 转换资源 ──▶ ③ 骨架 + Engine ──▶ ④ 委托跑通
        │                │                  │                  │
        └── 回归网 ──────┴── 图片/节点 ─────┴── FFI ───────────┴── 端到端
```

交付物：

1. 旧仓 `record_golden.py` 跑通，产出 12 个用例
2. `cargo test` 全绿（地基 + 领域，无需 SDK）
3. chroot 构建链跑通 `aarch64-unknown-linux-gnu`，能加载 `MAA-linux-aarch64`
4. `resource/` 由 `convert-images` + `convert-assets` 生成，`pipeline-check` 全绿
5. 委托 `CommissionStart → commission_done` 在真实模拟器跑通
6. `maazure-daemon` 能启动、列实例、看实时截图

**DoD**

- [ ] 委托连跑 **20 次无人工干预**
- [ ] 同一录像回放，L1+L2 断言与旧版一致
- [ ] 四项耗时实测：截图 / 模板 / OCR / Rust 决策
- [ ] DEC-007 结论：720 归一化后阈值漂移实测值
- [ ] GIF 模板数量统计与策略

> P0 的产出不是「一个能用的委托脚本」，而是**一条被验证过的生产线 + 一张回归网**。
> 委托只是证明生产线能出货的样品。

## P2 · 战役与战斗（6–10 周）

- `domain/battle::grid`（单应性 + 网格预测，移植 2,783 行）
- `domain/battle::map`（相机 + 舰队 + 寻路，5,522 行）
- `domain/battle::campaign`（4,905 行）
- `domain/battle::combat`（2,651 行）
- `data/campaign/` 全量 1,436 个地图

DoD：

- [ ] 主线每章至少一张图跑通
- [ ] 同图连跑 10 次，路线与旧版一致率 > 95%（允许等价解）
- [ ] 地图检测单帧 < 15ms
- [ ] 新活动 = 加目录 + 重跑 xtask，**不改 Rust**
- [ ] `CampaignEnd` / `OilExhausted` / `OilMaxed` 语义一致

## P4 · 外围与发布（4–6 周）

统计上报、MCP（18 个工具名不变）、Web UI、发布流水线、自动更新、崩溃报告、
用户迁移指南。

## 每阶段的三问阀（任一否，不进下一阶段）

1. **回放覆盖**：本阶段交付的模块有对应用例吗？（要求 100%）
2. **可回退**：用户此刻切回旧版，配置与数据完好？
3. **单人可维护**：新增一个同难度任务，能否 1 天内完成？

第 3 条最关键。如果写一个新任务还要改 5 个文件，说明抽象没做对，
继续堆功能只会把 288k 行的坑原样搬到 Rust。
