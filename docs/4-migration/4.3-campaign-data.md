# 4.3 · 战役数据迁移

**位置**：`4-migration` › 4.3 ｜ 前置：[4.2 资源](4.2-assets.md) ｜ 后继：[4.4 配置](4.4-config.md)

## 现状：数据即代码

`campaign/` 下 **1,436 个 `.py`**，形态高度规律：

```python
MAP = CampaignMap('12-4')
MAP.shape = 'K8'
MAP.camera_data = ['D2', 'D6', 'H2', 'H6']
MAP.map_data = """
    MB MB ME -- ME ++ ++ ++ MB MB ++
    ...
"""
MAP.weight_data = """
    50 50 ...
"""
MAP.spawn_data = [
    {'battle': 0, 'enemy': 2},
    ...
]
```

数据被编译进代码的后果：改一个格子要跑全量测试、活动下线要删代码、
新人看不出哪些是数据哪些是逻辑。

## 目标

```jsonc
// data/campaign/campaign_hard/12-4.json
{
  "_meta": { "source": "campaign/campaign_hard/campaign_12_4.py", "source_rev": "86a9463d4" },
  "chapter": "12-4",
  "shape": "K8",
  "camera_data": ["D2", "D6", "H2", "H6"],
  "camera_data_spawn_point": ["D6"],
  "map_data": ["MB MB ME -- ME ++ ++ ++ MB MB ++", "..."],
  "weight_data": [[50, 50, "..."]],
  "spawn_data": [{ "battle": 0, "enemy": 2 }],
  "flags": { "road_blocks": true },
  "inherits": null
}
```

## 提取策略（AST，只接受字面量）

| 情况 | 处理 |
|---|---|
| `str`/`int`/`float`/`list`/`dict`/`tuple`/三引号 | `ast.literal_eval` 直接取 |
| `MAP.xxx = <字面量>` | 记录字段 |
| `MAP.road_blocks()` 等调用 | 记录到 `flags` |
| `from campaign...import Config` | 记录 `inherits`，转换后合并 |
| 其它表达式 | **报错**，进入待人工清单，不猜 |

## 校验器（必须做）

| 检查 | 依据 |
|---|---|
| 行列数与 `shape` 一致 | `K`=11 列，数字=行数 |
| 每行 token 合法 | `{++, --, SP, ME, MB, MM, MA, MS, __, Me}` |
| `spawn_data` 的 `battle` 从 0 连续递增 | 旧版约定 |
| 转换后 Rust 读一遍 == 旧版 Python 读一遍 | 逐字段 diff |

第三项最容易漏：`spawn_data` 不连续说明提取时丢了行（三引号里混进空行是最常见原因）。

Rust 侧已有的解析器：`crates/domain/battle` 的 `Symbol` / `Shape` / `parse_map_rows`，
转换器直接复用它做自检。

## 实测（`86a9463d4`，`xtask convert-campaign`）

| 项 | 数值 |
|---|---|
| 扫描 `.py` | 1,436 |
| 其中地图文件 | 1,365 |
| 辅助文件（基类 / `__init__` / `campaign_hard` 等，无 `map_data`） | 71 |
| 写出 JSON | 1,365 |
| 目录结构 | 保留（`campaign_main/` `campaign_hard/` `war_archives_*` `event_*`） |
| 体积 | 5.9 MB |
| 校验失败 | **0** |
| `shape` 靠推断（旧文件从 Config 继承） | 39 |
| 未知地图符号 | 4 处（2 个 `SI`、2 个单 `-`） |
| 无法静态求值的字段 | 38 处（`grid_class` 28、动态 `spawn_data` 10） |

三处「不猜」的处理：

| 情况 | 处理 | 理由 |
|---|---|---|
| 无 `shape` | 按 `map_data` 行列推断，产物标 `shape_inferred: true` | 39 个活动图从 `Config` 继承形状，硬失败会白丢 39 个地图 |
| 未知 token（`SI`、`-`） | 保留原文 + 记入 `validation.unknown_tokens`，**不**当致命错误 | 数据要保真；运行时把未知 token 当不可通行即可 |
| 非字面量（`grid_class = Grid`、`spawn_data = make_spawn()`） | 记入 `unresolved` 清单，人工处理 | 静态求值不了，猜就是埋雷 |

`grid_class` 的 28 处都是同一模式（活动图自定义网格类），实际影响面小：
P2 移植时统一映射到默认网格。

## 部署

| 项 | 决定 |
|---|---|
| 位置 | `data/campaign/`，**不进 `resource/`**（它不是 MaaFW 资源） |
| 打包 | 运行时读文件，不用 `include_dir!`（1,436 个文件会让增量编译变慢） |
| 活动下线 | 删目录即可，不需要改 Rust 代码 |
| 新增活动 | 加目录 + 重跑 `xtask convert-campaign`，**不写代码**（P2 DoD） |

## 迁移顺序

```
campaign_main/      → 先做（推图主路径，用例最多）
campaign_hard/      → 次之
campaign_sos/       → 随 sos 任务
campaign_war_archives/ → 随作战档案
campaign_event/     → 按当前活动逐个加，不追溯历史活动
```

历史活动不迁移：它们已经过期，迁过来只是给 `pipeline-check` 增加噪声。
需要时从旧仓按需转换。
