# 4.4 · 配置迁移

**位置**：`4-migration` › 4.4 ｜ 前置：[4.3](4.3-campaign-data.md) ｜ 后继：[5.1 构建](../5-engineering/5.1-build.md)

## 现状：2,401 项

旧版用 4 层 YAML 管道（`task.yaml` + `argument.yaml` + `override.yaml` + `default.yaml`）
生成 `args.json`，GUI 渲染 2,401 项，运行时以 `Main.Campaign.Name` 点分路径访问。
拼错键名只在运行时 KeyError。

## 目标：PI v2 + 生成强类型

| 旧概念 | PI v2（v2.10.5） |
|---|---|
| `argument` 定义 | `option` + `case`（`select`/`checkbox`/`input`/`switch`） |
| `task.yaml` 的 任务→组 | `task` + `group` |
| 点分路径 `Main.Campaign.Name` | `option.name` + `pipeline_override` |
| `default.yaml` / `override.yaml` | `preset` + `option.default_case` |
| 5 语言 i18n | `languages` + `interface_<lang>.json` |
| `display: hide` | 不声明该 option |

## 关键决定：不是 1:1 平移

**默认只暴露每个任务 3–8 项真正会被改的配置**，其余用 `preset` 固定成合理默认。
2,401 → 约 250 项。

理由：旧版 GUI 里有大量「调过一次就再也没动」的项，它们是迁移成本和误配风险的来源。
有人提需求再放出来，是更便宜的演变方式。

| 任务 | 旧项数 | 新暴露项 | 收起的典型 |
|---|---|---|---|
| Commission | 12 | 4 | 内部超时、重试次数 |
| Research | 40+ | 8 | 各项目的优先级权重 |
| Campaign | 30+ | 6 | 地图检测内部阈值 |
| OpsiScheduling | 20+ | 5 | 内部状态文件路径 |

## 实测（`86a9463d4`，`xtask convert-config`）

| 项 | 数值 |
|---|---|
| 任务 | 94 |
| 参数 | 2,401 |
| 内部项（`storage` / `stored` / `state`） | 109 → 跳过 |
| `display: hide` | 522 → 跳过 |
| 生成 option（全量） | 1,770 |
| 生成 option（精选，被 `interface.json` import） | **740**（每任务 ≤10） |
| 可跑任务（入口节点已存在） | **1**（Commission） |
| 待接线任务（我放进 `tasks.planned.json`，不被 import） | 93 |
| 生成结构体 | 90 个任务 / 若干 group 子结构 |

精选的启发式（写在 `convert_config.rs` 里，可调）：

```
排序键 = 是否「看起来会被调」（组不在 Scheduler/Error/Optimization，
         名字不含 OCR/Timeout/RateLimit/Interval/Threshold/Retry）
       → 名字短的优先（短名通常是主开关）
       → 字典序
取前 10 个
```

砍掉的 1,030 项并没有丢：全量在 `interface.d/options.all.json` 里，谁需要谁加回
`tasks.json` 的 `option` 列表。

## 结构：三层嵌套，不能拍平

旧配置是 `{"Task": {"Group": {"Arg": value}}}`。第一版生成器把三层拍成一层
（`rename = "Arg"`），结果 loader 对真实配置永远读到 `None`——因为 group 那层没有对应的
字段。改成嵌套后：

```rust
pub struct Commission {
    #[serde(rename = "Commission", default)] pub commission: Option<CommissionCommission>,
    #[serde(rename = "Scheduler", default)]  pub scheduler:  Option<CommissionScheduler>,
}
pub struct CommissionCommission { #[serde(rename = "PresetFilter", default)] pub preset_filter: Option<String>, … }
```

字段一律 `Option`：旧配置经常缺组、缺字段，缺了就当「用默认值」，
不该在加载期报错。

## 生成物

```
interface.d/options.json          精选 option（被 interface.json import）
interface.d/options.all.json      全量 option（参考）
interface.d/tasks.json            可跑任务（被 import）
interface.d/tasks.planned.json    待接线任务（P1 清单）
interface.d/groups.json           分组（来自旧 menu.json 的 10 个键）
crates/domain/config/src/generated.rs   强类型（90 个任务结构体）
```

```rust
#[derive(Deserialize)]
pub struct CommissionConfig {
    #[serde(default = "def_receive")] pub receive: bool,
    #[serde(default)] pub skip_urgent: bool,
}
```

写错键名 → 编译期报错。这是相对旧版最实在的改进之一。

## 映射器

`xtask convert-config`：

1. 读 `args.json`，为每个 `(Task, Group, Argument)` 生成 `option`
2. `option.pipeline_override` 把取值注入节点（`expected` / `roi` / `threshold`）
3. `Task` 列表 → `task[]`，丢弃 `Scheduler.Command` 等内部字段
4. 生成 `interface.json` 骨架，人工补 `label` / `description` / `icon`
5. 生成 Rust 类型（`xtask` 用模板输出，不引第三方代码生成器）

## 用户迁移（P4）

用户已经调好的 `config/alas.json` 必须能过来，否则没人愿意切。

| 步骤 | 做法 |
|---|---|
| 读旧配置 | `maazure-daemon --migrate-config <path>` |
| 能映射的 | 按映射表写入新 `config/instance.json` |
| 不能映射的 | **不静默丢弃**，写入 `migration-report.md` |
| 双读 | 新配置不存在时回退读旧配置，让用户能慢慢迁 |

## i18n

- 从旧 `i18n/*.json` 按 key 直取，键名改 `task.name` / `option.name` 路径形式
- `zh-TW` 保留已有译文（旧版是自动简繁转换的，不要重转一遍把人工校对覆盖掉）
- 回退顺序沿用旧约定：`en → cn → jp → tw`
- CI 检查：`interface_*.json` 键集合必须与 `interface.json` 里出现的 `$key` 完全一致
