# 4.4 · 配置迁移

**位置**：`4-migration` › 4.4 ｜ 前置：[4.3](4.3-campaign-data.md) ｜ 后继：[5.1 构建](../5-engineering/5.1-build.md)

## 现状：2,401 项

旧版用 4 层 YAML 管道（`task.yaml` + `argument.yaml` + `override.yaml` + `default.yaml`）
生成 `args.json`，GUI 渲染 2,401 项，运行时以 `Main.Campaign.Name` 点分路径访问。
拼错键名只在运行时 KeyError。

## 目标：PI v2 + 生成强类型

| 旧概念 | PI v2（v2.10.5） |
|---|---|
| `argument` 定义 | `option` + `case`（`select`/`checkbox`/`input`/`switch`） |
| `task.yaml` 的 任务→组 | `task` + `group` |
| 点分路径 `Main.Campaign.Name` | `option.name` + `pipeline_override` |
| `default.yaml` / `override.yaml` | `preset` + `option.default_case` |
| 5 语言 i18n | `languages` + `interface_<lang>.json` |
| `display: hide` | 不声明该 option |

## 关键决定：不是 1:1 平移

**默认只暴露每个任务 3–8 项真正会被改的配置**，其余用 `preset` 固定成合理默认。
2,401 → 约 250 项。

理由：旧版 GUI 里有大量「调过一次就再也没动」的项，它们是迁移成本和误配风险的来源。
有人提需求再放出来，是更便宜的演变方式。

| 任务 | 旧项数 | 新暴露项 | 收起的典型 |
|---|---|---|---|
| Commission | 12 | 4 | 内部超时、重试次数 |
| Research | 40+ | 8 | 各项目的优先级权重 |
| Campaign | 30+ | 6 | 地图检测内部阈值 |
| OpsiScheduling | 20+ | 5 | 内部状态文件路径 |

## 生成物

```
crates/foundation/core/src/config/generated.rs   ← #[allow(dead_code)]
interface.json                                    ← schema 源
interface_zh_cn.json / _en_us / _ja_jp / _zh_tw   ← 译文
```

```rust
#[derive(Deserialize)]
pub struct CommissionConfig {
    #[serde(default = "def_receive")] pub receive: bool,
    #[serde(default)] pub skip_urgent: bool,
}
```

写错键名 → 编译期报错。这是相对旧版最实在的改进之一。

## 映射器

`xtask convert-config`：

1. 读 `args.json`，为每个 `(Task, Group, Argument)` 生成 `option`
2. `option.pipeline_override` 把取值注入节点（`expected` / `roi` / `threshold`）
3. `Task` 列表 → `task[]`，丢弃 `Scheduler.Command` 等内部字段
4. 生成 `interface.json` 骨架，人工补 `label` / `description` / `icon`
5. 生成 Rust 类型（`xtask` 用模板输出，不引第三方代码生成器）

## 用户迁移（P4）

用户已经调好的 `config/alas.json` 必须能过来，否则没人愿意切。

| 步骤 | 做法 |
|---|---|
| 读旧配置 | `maazure-daemon --migrate-config <path>` |
| 能映射的 | 按映射表写入新 `config/instance.json` |
| 不能映射的 | **不静默丢弃**，写入 `migration-report.md` |
| 双读 | 新配置不存在时回退读旧配置，让用户能慢慢迁 |

## i18n

- 从旧 `i18n/*.json` 按 key 直取，键名改 `task.name` / `option.name` 路径形式
- `zh-TW` 保留已有译文（旧版是自动简繁转换的，不要重转一遍把人工校对覆盖掉）
- 回退顺序沿用旧约定：`en → cn → jp → tw`
- CI 检查：`interface_*.json` 键集合必须与 `interface.json` 里出现的 `$key` 完全一致
