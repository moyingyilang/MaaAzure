# 4.6 · 委托扫描的数据采集怎么落

**位置**：`4-migration` › 4.6 ｜ 相关：[4.5 任务移植](4.5-task-porting.md)

## 上游怎么做的

```python
def _commission_scan_list(self):
    commission = SelectedGrids([])
    for _ in range(15):
        new = self.commission_detect(trial=2)   # OCR 当前一屏，返回 Commission 对象列表
        commission = commission.add_by_eq(new)  # 按 key 去重合并
        if not self._commission_swipe():        # 滑不动了 = 到底
            break
    return commission
```

`commission_detect` 对每张委托卡做 OCR，产出 `Commission` 对象
（名字、剩余时间、状态、是否紧急）。

## 为什么不能只用 Pipeline 节点

MaaFW 的节点是**无状态**的：一次识别只回答「这一帧有没有 X」，
没有跨帧累积的容器。而扫描的本质是**跨帧累积一张列表**。

节点能做的：滚动、点击、单帧识别。
节点做不到：把 15 帧里识别到的 150 张委托去重合并成一张表。

## 决定：两段式

| 阶段 | 归属 | 职责 |
|---|---|---|
| 采集 | Rust `custom_recognition: CommissionScan` | 每帧对列表区域做 OCR，累积到共享状态（按名字+位置去重） |
| 滚动 | Pipeline 节点 | `Swipe` 动作把列表往下翻，直到 `CommissionScan` 报告「没有新卡片」 |
| 决策 | Rust `custom_recognition: CommissionPick` | 读累积结果，按上游 `_commission_choose` 的规则选出要派的委托 |

Pipeline 侧的形状：

```jsonc
"commission_scan_swipe": {
  "recognition": "Custom", "custom_recognition": "CommissionScan",
  "action": { "type": "Swipe", "param": { "begin": [1257, 660], "end": [1257, 190], "duration": 600 } },
  "post_delay": 800,
  "next": ["commission_scan_swipe", "commission_pick"]   // 还有新卡就继续滑
}
```

`CommissionScan` 的返回值语义：**命中 = 这一帧还有没见过的委托**。
滑到底时它不再命中，`next` 自然落到 `commission_pick`。

这样「一直滑」不再是靠 `max_hit` 拍的次数，而是由**数据**决定的终止条件。
