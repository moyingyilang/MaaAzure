# 4.1 · 图片迁移

**位置**：`4-migration` › 4.1 ｜ 前置：[2.1 分层](../2-architecture/2.1-layers.md) ｜ 后继：[4.2 资源](4.2-assets.md)
**实现**：`crates/apps/xtask/src/convert_images.rs`（已落地，实测数据见 §6）

## 1. 迁移的判据：只搬被引用的

旧仓 `assets/` 有 7,786 张 PNG、969 个 GIF，但目录里同时存在大量**未被任何 `assets.py` 引用**的
历史残留。全量拷贝只会给 `pipeline-check` 增加噪声。

所以 `convert-images` 的输入不是目录树，而是 **61 个 `assets.py` 里声明的 `file=` 路径**。

## 2. 映射规则

```
旧                                            新（每个服务器一个资源包）
assets/cn/commission/X.png              →     resource/cn/image/commission/<node>.png
assets/cn/template/X.gif                →     resource/cn/image/template/<node>/frame_00.png …
assets/en/...                           →     resource/en/image/...
```

包结构（运行时按 `common` → `<server>` 顺序加载，后者覆盖前者）：

```
resource/
├── common/                 手写拓扑 + default_pipeline.json（服务器无关）
│   ├── default_pipeline.json
│   └── pipeline/0-common/… 1-daily/…
├── cn/ en/ jp/ tw/         每个服务器：生成的叶子 + 自己的图
│   ├── pipeline/gen/<module>.json
│   └── image/<module>/<node>[.png|/]
└── image_index.json        全部引用的清单
```

这样**包内路径不含 server 段**，`template` 可以直接写 `commission/commission_start.png`，
不用在运行时做路径拼接或 pipeline 覆盖。

三条规则各有原因：

| 规则 | 原因 |
|---|---|
| **server 取 `file` 字典的键**，不从路径推断 | 旧仓大量条目把 `en/jp/tw` 指向 cn 的同一张图（美术复用）。逻辑服务器才是资源包该放的目录 |
| **每个服务器独立成包** | 换服务器 = 换资源包，不需要运行时改路径；PI 的 `resource` 天然表达"选服务器" |
| **`module` 取 `assets.py` 所在目录名** | 与 `pipeline/gen/<module>.json` 对齐，一个模块一棵子树 |
| **`node` = `(module, constant)` 的纯函数**（见 §3） | 可逆：图片路径能推回节点名，`pipeline-check` 才能校验引用 |
| **子目录被拍平** | 节点名已唯一（实测冲突 0），拍平后路径可预测 |
| **GIF 抽帧成目录** | MaaFW 的 `template` 支持目录路径（递归加载），等价「任一帧命中即命中」，比逐帧写节点干净 |

## 3. 命名：`TEMPLATE_` 前缀**保留**

```
constant  TEMPLATE_RUNNING         (module = research)
  │ 小写 + 非法字符压成 _
  ▼
base      template_running
  │ 不以 module 开头 → 加前缀
  ▼
node      research_template_running
```

最初设计是「剥掉 `TEMPLATE_` 前缀」，实测在 2,753 条声明里产生 **9 处冲突**
（同一模块同时存在 `TEMPLATE_RUNNING` 与 `RESEARCH_RUNNING`、`TEMPLATE_BUSINESS_SHOP_GRILL`
与 `BUSINESS_SHOP_GRILL`……它们是两张不同的图）。剥前缀就必须引入重命名表，
而重命名表破坏可逆性。**保留前缀后冲突降为 0，命名重新成为纯函数。**

## 4. 索引

产物 `resource/image_index.json`（约 1 MB，**入库**）：

```jsonc
{
  "_meta": {
    "tool": "xtask convert-images",
    "source_root": "../AzurPilot",
    "source_rev": "86a9463d4",           // 追溯「这张图来自哪一版」
    "schema_doc": "docs/4-migration/4.1-images.md",
    "counts": { "decls": 2753, "with_files": 2753, "png": 10028, "gif": 984, "frames": 4402 }
  },
  "entries": {
    "commission::COMMISSION_START": {
      "module": "commission", "kind": "button", "node": "commission_start",
      "has_animated": false,
      "images": {
        "cn": "image/cn/commission/commission_start.png",
        "en": "image/en/commission/commission_start.png"
      }
    },
    "handler::POPUP_CONFIRM": {
      "module": "handler", "kind": "button", "node": "handler_popup_confirm",
      "has_animated": true,
      "images": { "cn": "image/cn/handler/handler_popup_confirm/" }   // 尾斜杠 = 目录
    }
  },
  "skipped": [], "missing": [], "collisions": []
}
```

两个设计细节：

- 索引键是 `module::constant`。只按 constant 做键会跨模块互相覆盖（实测丢 32 条）。
- 目录用**尾斜杠**自描述。另设 `animated` 布尔字段会在「同一节点的 cn 是 GIF、jp 是 PNG」时
  撒谎（实测 7 个混合条目）。

## 5. 入库策略

| 产物 | 体积 | 入库 | 理由 |
|---|---|---|---|
| `resource/{cn,en,jp,tw}/image/` 138 MB | 唯一内容 40 MB | ✅ | 仓库自包含才能直接跑；git 按内容存 blob，重复的 5,831 份只存一次 |
| `resource/image_index.json` 1 MB | — | ✅ | 清单是 `pipeline-check` 的输入，且是文本，diff 可读 |
| `assets/` 原目录 | 152 MB | ❌ | 旧仓冻结，不复制 |

若将来 clone 体积成为问题，备选顺序：①发布包里带图片、仓库只留索引；
②Git LFS；③按服务器拆子模块。现在不预先优化。

## 6. 实测结果（`86a9463d4`）

| 项 | 数值 |
|---|---|
| 声明总数 | 2,753（`button` 2,072 + `template` 681） |
| 涉及模块 | 61 |
| 目标路径 | 11,012（每声明 4 个服务器） |
| 静态 PNG | 10,028 |
| 动图 | 984 个 → 4,402 帧（均值 4.5 帧，上限 64） |
| 含动图的条目 | 251（其中 243 在 `template` 模块，即共享动效池） |
| 缺失 / 冲突 / 跳过 | **0 / 0 / 0** |
| 磁盘 | 138 MB（唯一内容 40.3 MB，分布 4 个包） |
| 重复内容 | 5,831 份 / 55.8 MB（git 侧去重） |
| 耗时 | 约 11 秒（含 984 个 GIF 解码） |

## 7. 已知限制

| 限制 | 现状 | 后续 |
|---|---|---|
| 硬链接去重 | Android 应用数据区 `link(2)` 返回 **EPERM**，实测不可用 | 不做；只统计冗余量 |
| 缩放后的阈值漂移 | 未验证（P0 DoD 项） | 取 20 张代表图，在原生 720p / 归一化 / `display_raw` 三档记录分数分布 |
| 动图帧抽取上限 | 64 帧 | 实测最多 5 帧，上限只是防炸 |
| 索引不含尺寸 | 未记录宽高 | 需要时读 PNG IHDR（13 字节）即可，不必解码 |
