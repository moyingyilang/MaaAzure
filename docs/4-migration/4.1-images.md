# 4.1 · 图片迁移

**位置**：`4-migration` › 4.1 ｜ 后继：[4.2 资源](4.2-assets.md)

## 现状 → 目标

```
AzurPilot/assets/                     MaaAzure/resource/image/
├── cn/                               ├── cn/
│   ├── commission/                   │   ├── commission/
│   │   └── COMMISSION_START.png      │   │   └── start.png
│   ├── map/                          │   ├── map/
│   └── ...                           │   └── ...
├── en/  jp/  tw/                     ├── en/  jp/  tw/
└── 7,786 张 / 152 MB                 └── 同规模
```

转换器：`xtask convert-images`（P0 第一个工具）。

## 四条规则

1. **保留 server 一级目录。** MaaFW 的 bundle 是「后加载覆盖同路径」，
   多服务器靠加载不同路径实现：`path: ["./resource", "./resource/cn"]`。
   不需要像旧版那样在资源里做变量替换，比旧版干净。
2. **文件名小写下划线**，与节点名一致（`COMMISSION_START` → `start.png`）。
3. **不改像素。** 1280×720 的裁图原样保留，靠 Controller 的 `display_short_side: 720` 归一化。
4. **GIF 不支持。** 旧版 `Template` 支持动图，MaaFW 只吃静态图。需先统计再定策略。

## 必须产出的索引

```jsonc
// resource/image_index.json
{
  "_meta": { "source_rev": "86a9463d4", "count": 7786 },
  "assets/cn/commission/COMMISSION_ADVICE.png": {
    "new": "cn/commission/advice.png",
    "module": "commission",
    "constant": "COMMISSION_ADVICE"
  }
}
```

索引是后续所有步骤的对照依据（[4.2](4.2-assets.md) 要用它、回滚要用它）。

## 待办：GIF 与阈值

| 项 | 做法 | 何时 |
|---|---|---|
| GIF 模板数量统计 | `find assets -name '*.gif' \| wc -l`，逐个决定「取首帧」或「拆成多节点」 | P0 第一天 |
| 归一化后阈值漂移 | 取 20 张代表性模板，在原生 720p / 归一化 720p / `display_raw` 三档下记录匹配分数分布 | P0 DoD |
| 压缩伪影 | 禁止把回放/归档帧转成 JPEG 后当模板 | 永久 |

## 体积

152 MB 原图。发布包要控制体积：

| 方案 | 体积 | 代价 |
|---|---|---|
| 原样 PN G | 152 MB | 下载慢 |
| PNG 重压缩（`oxipng -o4`） | ~110 MB | 需一次性处理，像素不变（无损） |
| 只保留 cn + en | ~76 MB | 失去 jp/tw 支持 |
| 按需分平台包 | 按需 | 打包脚本复杂 |

**P1 决策**：先原样迁移保证正确性，发布前统一跑一次无损重压缩。
